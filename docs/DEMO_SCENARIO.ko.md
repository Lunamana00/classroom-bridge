## 3. 장면별 대사와 화면

### 장면 1. 교수의 첫 수업 개설

교수 브라우저에서 로그인한 뒤 `새 수업`을 연다. 기존 수업이 있으면 그대로 두고 새 수업 개설을 진행한다. 다음을 입력한다.

```text
수업 이름: CS231n 2026
수업 소개: 이미지 분류부터 CNN, Attention과 Transformers까지, 제공된 CS231n 강의자료와 코드로 컴퓨터 비전을 학습합니다.
```

`수업 만들기`를 누르고 담당 교수 역할과 빈 수업을 확인한다.

**내레이션**

> 한 학기 수업을 만들고, 이 수업에서 사용할 자료를 등록합니다. 학생의 질문과 퀴즈 응답도 이 수업에 연결됩니다.

### 장면 2. 전체 강의자료 등록

`강의자료`에서 역전파 복습 PDF를 업로드하고 제목과 원문을 확인한다. 다음으로 같은 폴더 notebook에서 추출한 코드 하나를 등록한다. PDF는 페이지를, 코드는 원문 구간을 출처로 보여 준다.

여기서 컷을 넣어 나머지 전체 PDF·코드를 일괄 등록한다. 촬영을 다시 시작하면 강의자료 목록을 스크롤하며 초반 이미지 분류·최적화, CNN, Attention/Transformers, 후반 강의와 보충 자료가 함께 들어 있음을 보여 준다. 대표 자료 몇 개를 열어 실제 내용도 확인한다.

**내레이션**

> CS231n 폴더에 제공된 PDF와 코드 전체를 한 수업에 담았습니다. 오늘은 역전파를 중심으로 진행합니다. 학생 질문에 활용하기 전에, 자료에서 추출한 핵심 개념과 원문을 교수가 확인합니다.

자료 개수는 실제 등록 결과를 사용한다. 제공 폴더에 파일이 없는 강의까지 들어 있다고 설명하지 않는다. 일괄 등록 방법과 원본 대조는 운영 부록에서 다룬다.

### 장면 3. 핵심 개념 추출·검토·승인

교수 웹의 `핵심 개념`을 연다. 방금 등록한 대표 자료의 `자료별 추출 현황`에서 `추출 대기 → 개념 추출 중 → 추출 완료`를 확인한다. 처리 중에는 자동 갱신되며 필요하면 `새로고침`을 누른다. 완료를 기다린 구간은 컷으로 줄이고 실제 완료 화면으로 이어 붙인다.

기존 자료가 `추출 전`이면 `핵심 개념 추출`을 누른다. `추출 실패` 또는 `추출 설정 필요`가 나오면 그 상태를 그대로 확인하고 준비 담당자가 원인을 해결한 뒤 `다시 추출`한다. 실패를 일부러 만들거나 완료한 것처럼 편집하지 않는다. 내용이 짧은 코드 셀은 작업이 완료되어도 개념이 0개일 수 있다.

**교수의 말 또는 내레이션**

> 자료에서 어떤 핵심 개념들을 찾았는지 먼저 확인해 볼게요.

1. `검토 대기` 개념 하나에서 `검토·승인`을 연다. 이름·설명·동의어와 실제 자료 제목·페이지·원문을 함께 읽는다.
2. 설명을 다듬을 부분이 실제로 있으면 `초안 수정`에서 이름·설명·별칭 또는 근거를 고친다. `초안 저장 후 검토`로 돌아와 바뀐 내용을 다시 확인한다. 저장만으로 승인되지 않는다.
3. 검토 확인 체크를 누른 뒤 `승인하고 개념 등록`을 누른다. 목록에서 `승인됨`을 확인한다.
4. 실제로 같은 개념을 가리키는 통합 제안이 있으면 기존 정의·추가 별칭·각 원문을 비교한 뒤 `승인하고 개념 통합`을 보여 준다. 제안이 없으면 올바른 대상이 있을 때만 편집 화면의 `중복 개념 통합`을 선택한다. 서로 관련되기만 한 다른 개념을 시연을 위해 합치지 않는다.
5. 필요 없거나 잘못 추출된 초안이 실제로 있으면 `초안 제외`를 사용한다. `검토 대기 / 승인됨 / 전체 이력` 필터로 등록·통합·제외 결과를 확인한다. 적절한 대상이 없으면 이 기능은 에필로그로 남긴다.

**화면에서 교수가 자연스럽게 말할 수 있는 문장**

> 이 설명은 조금 더 쉽게 고쳐 두자. 원문에서는 어떤 표현을 썼지?

> 이 둘은 같은 개념을 말하는 것 같네. 정의와 근거를 비교하고 하나로 정리할게.

개념 수정·승인·제외·통합은 **교수 웹에서 직접 수행**한다. AI가 개념과 진행 상태를 설명하거나 추출을 요청할 수 있지만, 교수의 자연어 한마디만으로 개념 승인이 완료됐다고 묘사하지 않는다. 이후 장면의 퀴즈 배포 승인은 별도의 절차다.

전체 자료의 나머지 추출·검토·승인 준비는 여기서 녹화를 멈추고 마친다. 영상에 쓰는 단원의 개념과 출처가 준비됐는지 확인한 뒤 이어 간다. 개념 승인 수가 0개인 상태에서 질문하면 `수업 개념 준비가 필요해요`가 표시된다. 이는 질문이 자료 밖이라는 판단과 다르다. 준비 전·후를 보여 주고 싶으면 별도 짧은 삽입 컷으로 남긴다. 이때 입력한 예비 질문도 수업 기록에 포함되므로 나중의 질문 수를 설명할 때 시연용 질문이 포함됐음을 구분한다.

**내레이션**

> AI가 자료에서 핵심 개념과 원문 근거를 정리합니다. 교수는 설명과 중복 제안을 검토하고, 확인한 개념을 수업에서 사용하도록 승인합니다. 이 승인과 학생에게 낼 퀴즈의 배포 승인은 따로 이루어집니다.

### 장면 4. 학생 초대와 참여

교수 화면에서 `학생 초대` 링크를 만들고 복사한다. 학생 프로필에서 링크를 열어 별도 Google 계정으로 로그인하고 수업에 참여한다. 학생에게도 `CS231n 2026`과 같은 자료 목록이 보이는지 확인한다.

교수 화면의 `참여자 관리`에서 담당 교수와 학생을 확인한다. 학생 화면에서는 수업 현황·전체 응답 분석·자료 삭제·핵심 개념 관리·퀴즈 관리가 보이지 않는 것을 잠깐 보여 준다.

**내레이션**

> 학생은 초대받은 수업에 참여합니다. 같은 자료로 공부하지만 전체 질문 분석과 수업 관리는 교수에게만 열립니다.

### 장면 5. 교수의 AI와 대화 시작

교수의 AI 연결을 완료하고 다음처럼 말한다.

```text
CS231n 2026 수업을 같이 준비해 보자. 어떤 자료들이 들어 있는지 간단히 정리해 줄래?
```

AI가 수업을 선택하고 실제 등록 자료를 확인하는 모습을 보여 준다. 여러 수업이 있어 AI가 물으면 교수는 `CS231n 2026이야.`라고 답한다. AI가 찾은 자료의 범위 안에서 수업 구성을 설명하는지 확인한다.

자료 등록 기능을 AI 대화에서도 보여 주려면, 일괄 등록에서 잠시 제외해 둔 코드 원문 하나를 첨부하거나 붙여 넣고 요청한다.

```text
이 코드도 우리 수업 자료에 넣어줘. 원문 그대로 보관해 줘.
```

웹 자료 목록을 새로고침해 실제 등록과 개념 추출 상태를 확인한다. 방금 추가한 내용도 개념 초안을 검토·승인한 뒤 학생 질문에 사용한다. 이미 등록한 원문이라면 다시 넣지 않고 기존 자료와 추출·승인 상태를 확인한다.

개념 준비 상태를 AI에게 확인하는 장면도 남긴다.

```text
자료에서 정리된 핵심 개념들은 준비됐어? 내가 확인할 부분이 있으면 알려줘.
```

이미 등록했지만 추출하지 않은 자료가 실제로 있을 때는 해당 자료를 가리키며 요청한다.

```text
이 자료도 핵심 개념을 정리해 줘. 끝나면 내가 원문과 같이 확인할게.
```

AI가 추출을 요청하고 웹 검토 화면으로 안내하는지 확인한다. 개념 승인은 웹에서 마친다.

**내레이션**

> 교수는 수업 이름과 원하는 일만 말합니다. 어느 수업의 자료를 확인하고 어떻게 처리할지는 AI가 연결된 수업 기능을 이용해 알아서 진행합니다.

### 장면 6. 오늘 수업의 이해 확인 퀴즈 만들기

교수는 오늘 다룬 단원과 원하는 결과를 말한다.

```text
오늘은 역전파를 설명했어. 학생들이 핵심을 이해했는지 확인할 짧은 퀴즈를 만들어 줄래? 객관식과 단답형을 섞어서 우선 보여줘.
```

AI가 등록 자료에서 근거를 확인하고 초안을 제안한다. 문제·선택지·정답·해설·출처를 교수에게 보여 주며 아직 학생에게 배포하지 않은 상태를 확인한다.

교수는 대화로 검토를 요청한다.

```text
정답과 해설도 같이 보자. 이 문제들이 오늘 설명한 내용과 잘 맞는지 확인해 줘.
```

검토한 정확한 문항을 보고 교수가 직접 승인한다.

```text
좋아, 이대로 학생들에게 내줘.
```

AI의 성공 확인과 웹의 `배포 중` 상태를 보여 준다. AI가 승인 전에 먼저 게시하거나 교수의 승인 답변을 대신 만들어서는 안 된다. 검토 이후 내용이 바뀌면 바뀐 문항을 다시 확인하고 승인한다.

웹 경로도 별도 문항 하나로 짧게 보여 준다. `퀴즈 초안 만들기`에서 문항을 저장하고 `초안 수정`으로 표현을 다듬는다. `검토 후 배포`에서 문제·정답·출처를 읽고 확인 체크박스와 `승인하고 학생에게 배포`를 누른다. 이 경로에서는 교수의 클릭이 최종 승인이다.

**내레이션**

> AI가 만든 문제는 바로 배포되지 않습니다. 교수는 내용과 출처를 읽고, 쓰기로 결정한 문항만 승인합니다. 대화에서 승인할 수도 있고 웹에서 검토한 뒤 배포할 수도 있습니다.

고정된 통계 시연용 네 문항은 운영 부록의 준비 도구로 따로 만들 수 있다. 본편의 교수에게 그 문구를 그대로 입력하거나 정해진 내부 값을 맞추도록 요구하지 않는다.

### 장면 7. 학생이 질문하고 퀴즈에 답하기

학생 웹의 질문 화면에서 오늘 배운 내용을 묻는다.

```text
역전파에서 왜 upstream gradient와 local gradient를 곱하나요?
```

학생 결과에서 먼저 `선별한 핵심 개념`의 이름·설명·선별 이유를 보여 준다. 승인되고 원문 근거가 남아 있는 개념 중 어떤 내용을 선택했는지 확인한다. 이어 실제 원문 발췌와 출처를 열어 자료 제목·페이지를 대조한다. 개념 관련성 점수를 정답 확률이나 계산 검증 결과라고 설명하지 않는다.

웹의 발췌 화면은 생성된 설명이 아니라는 표시를 남긴다. 답변 지시문 열기·복사 기능도 짧게 보여 준다. 준비한 개념이 없다는 안내가 나오면 승인 상태와 출처를 확인한 뒤 촬영을 재개한다.

관련 퀴즈가 나오면 학생은 문제를 읽고 직접 답한다. 오답 한 번을 제출해 정답과 해설이 **제출 후** 공개되는 모습을 보여 준다. 문항이 전달되기 전에 미리 정한 기호를 무조건 입력하지 않는다.

이어서 학생의 AI에서 같은 개념을 묻는다.

```text
CS231n 2026에서 배운 역전파가 아직 헷갈려. upstream gradient와 local gradient를 왜 곱하는지 계산 예시로 설명해 줘.
```

AI가 선택한 개념을 설명의 순서로 활용하고, 실제 원문으로 구체적인 계산·주장을 뒷받침하며 자료 제목·페이지를 인용하는 모습을 보여 준다. 관련 퀴즈를 제시한 뒤 학생의 답을 기다리는지 확인한다. 학생은 제시된 문항을 읽고 다음처럼 답한다.

```text
내 답은 A야.
```

위 `A`는 화면의 실제 문항에서 고른 답으로 바꾼다. AI가 학생 대신 답하거나 임의로 채점하지 않고 서버 결과를 알려 주는지 확인한다.

### 장면 8. 다시 풀기와 본인 응답 확인

학생이 이전에 틀린 개념을 다시 확인한다.

```text
아까 틀린 개념을 다시 확인해 보고 싶어. 비슷한 내용을 한 번 더 풀어 볼래.
```

새로 제시된 문항에 학생이 직접 답한다. 같은 문항을 다시 풀었다면 첫 응답과 재풀이가 구분되는 모습을 보여 준다.

```text
지금까지 내가 푼 결과를 보여줘. 처음에 틀린 것과 다시 풀어서 맞힌 것을 구분해서 알려줘.
```

본인 결과만 조회하며 다른 학생의 이력이 나오지 않는지 확인한다. 학생 웹의 `나의 개념 퀴즈 응답`도 새로고침한다. 미응답 문제를 오답으로 세지 않고, 개념별 첫 응답이 적으면 자료 부족으로 표시되는 것이 정상이다.

교수도 웹의 학생 질문 체험에서 퀴즈 하나를 풀어 본다. `교수 미리보기 · 집계 제외` 표시를 보여 주고 학생 통계에 추가되지 않았음을 확인한다. 교수의 질문 자체가 기록되는 것과 퀴즈 집계 제외는 구분한다.

### 장면 9. 한 단원을 넘어 수업 자료 활용하기

서로 연결된 여러 개념을 묻는 질문을 먼저 짧게 보여 준다.

```text
연쇄법칙과 ReLU의 미분은 역전파에서 어떻게 연결돼? 수업에서 본 코드랑 같이 설명해 줘.
```

질문에 실제 필요한 개념들과 각각의 선택 이유가 반환되는지 확인한다. 특정 개수의 개념이 반드시 나올 것이라고 미리 정하지 않는다. 여러 개념을 골랐다는 사실만으로 원문 근거가 충분하거나 풀이가 정확하다고 단정하지 않는다.

다른 단원 질문과 코드 질문도 삽입 컷으로 보여 준다. 아래 문장은 촬영할 개념·출처를 승인한 뒤 최신 검색 방식으로 다시 확인한다. 이전 검색 방식에서 성공했던 결과를 그대로 보장하지 않는다.

```text
CNN에서 max pooling도 학습되는 파라미터가 있나요?
```

```text
Transformer의 self-attention은 입력 안에서 어떤 정보를 섞는 건가요? 수업 자료로 설명해 주세요.
```

```text
이 코드에서 ReLU를 지난 뒤 음수 입력의 기울기를 0으로 만드는 이유가 뭐야?
```

코드 질문에는 지정 notebook에서 추출한 해당 코드 원문을 함께 보여 줄 수 있다. PDF를 근거로 답할 때는 자료 제목·페이지, 코드에는 자료 제목·원문 구간을 표시한다. 전체 자료의 등록과 승인 개념의 검색 범위는 구분한다. 기본 GPT 검색은 승인되고 출처가 남아 있는 전체 개념과 그 연결 원문을 검토하지만, 승인 개념에 연결되지 않은 모든 자료 구절까지 읽었다고 설명하지 않는다.

마지막으로 자료에 없는 질문을 한다.

```text
다음 시험은 언제, 어느 강의실에서 봐?
```

관련 승인 개념과 근거를 찾지 못하면 근거 부족을 알리고 날짜·장소를 만들어 내지 않는지 확인한다. 이때는 수업의 개념 준비가 끝난 상태여야 하며, 개념 승인 0개로 인한 준비 필요 안내를 자료 밖 질문 처리로 대신 보여 주지 않는다.

**내레이션**

> 학생은 오늘 수업뿐 아니라 다른 단원과 코드도 질문할 수 있습니다. 답을 뒷받침하는 자료가 없으면 모른다고 알립니다.

### 장면 10. 교수의 이해 확인

학생의 질문과 응답이 쌓인 뒤 교수는 평소처럼 묻는다.

```text
학생들이 오늘 수업을 잘 이해하고 있나?
```

AI는 오늘 역전파 수업이라는 앞 대화의 맥락을 사용해 실제 질문과 퀴즈 응답을 확인한다. 응답한 학생 수·첫 응답·오답이 나온 개념을 근거로 말하고, 질문이 많다는 이유만으로 성적이나 숙달도를 단정하지 않는지 확인한다. 기록이 적다면 적다는 점을 자연스럽게 설명해야 한다. 통계는 수업에 누적된 기록이므로 앞 대화에서 “오늘”이라고 말했어도 날짜별·단원별로 필터링된 결과라고 표현하지 않는다.

교수는 한 번 더 묻는다.

```text
특히 어디에서 많이 막히는 것 같아? 그렇게 본 이유도 같이 알려줘.
```

웹 화면으로 전환해 실제 기록을 대조한다.

1. `수업 현황`을 새로고침해 전체 질문·근거 있는 질문·근거 부족·자료 수를 확인한다. 새 검색 질문의 주제는 선택된 대표 개념으로 집계될 수 있다. 과거 단어 기반 기록과 분류 방식이 섞여 있으면 구분한다.
2. 질문 주제의 `전체 주제 / 상위 5개`를 전환한다.
3. 주제 막대를 눌러 해당 질문 목록을 열고, `전체 통계`와 주제 필터를 보여 준다.
4. 목록이 20건을 넘는 별도 통계 컷에서는 `다음 / 이전`으로 페이지가 바뀌는 것을 확인한다. 20건 이하면 버튼이 비활성인 상태를 그대로 보여 준다.
5. `개념 퀴즈`에서 첫 응답·정오답·반복을 보고 `학생별 응답 현황`을 펼친다.

**내레이션**

> 교수는 복잡한 통계 기능을 지정하지 않아도 질문과 응답을 함께 살펴볼 수 있습니다. AI의 해석은 실제 기록으로 다시 확인합니다.

### 장면 11. 다음 수업에 추가할 설명 준비

```text
다음 수업에 추가로 설명하면 좋을 부분은?
```

AI가 관측된 어려움과 관련 자료를 근거로 보충할 부분을 제안하면 요청을 이어 간다.

```text
그중 가장 필요한 부분으로 5분 정도의 보충 설명을 준비해 줘. 칠판에서 같이 풀 쉬운 계산 예시도 하나 넣어줘.
```

출처가 있는 설명안과 예시를 확인한다. 웹의 `보충 설명 준비`에서 같은 기록을 활용하는 지시문도 열고 복사한다. 새로 작성한 설명안은 검토할 결과물이며, 별도 요청 없이 원본 강의자료로 등록하지 않는다.

**내레이션**

> 학생이 어디에서 막혔는지 보고 다음 수업에서 어떻게 설명할지 이어서 준비합니다. 교수는 필요한 결과를 말하고 내용에 집중합니다.

### 장면 12. 여러 단원을 아우르는 시험 준비

```text
이 수업에서 배운 내용을 고르게 확인할 수 있게 확인 시험 6문제를 만들어 줘. 쉬운 문제와 생각이 필요한 문제를 섞고, 정답과 해설도 같이 보여줘.
```

AI가 수업 자료와 질문·퀴즈 응답을 확인해 출제안을 준비하고 출처를 제시하는 모습을 보여 준다. 학생들이 자주 틀린 개념을 다시 확인하되, 그 결과를 실제 시험 난이도나 성적 분포로 단정하지 않는다. 근거로 제공된 자료의 범위 안에서 초안을 작성하고 전체 강의의 모든 페이지를 검토했다고 과장하지 않는다.

교수는 필요하면 더 구체화한다.

```text
역전파에만 치우치지 않게 이미지 분류, CNN, Attention 내용도 함께 확인할 수 있으면 좋겠어.
```

웹의 `시험 출제 계획`에서도 문항 수를 6으로 바꾸고 계획·출제 지시문·복사 기능을 보여 준다. 최종 문항은 교수가 검토할 초안으로 남긴다.

**내레이션**

> 수업 전체 자료와 학생의 질문·응답이 다음 수업의 설명과 시험 준비로 이어집니다. 교수는 AI에게 평소 하듯 요청하고, 출처와 결과를 검토합니다.

## 4. 관리 기능 에필로그

앞 장면을 먼저 촬영한 뒤 진행한다. 관리 기능에서 내용을 바꾸면 앞서 본 결과가 달라질 수 있다.

| 순서 | 교수·학생의 행동 | 확인할 결과 |
|---|---|---|
| 1 | 쓰지 않을 퀴즈 초안을 보관 | 미게시 초안이 보관됨 |
| 2 | 게시된 시연 문항 하나의 배포 중단 | 이후 질문에 그 문항이 새로 전달되지 않음. 기존 기록은 유지 |
| 3 | 지정 코드 원문을 `직접 입력`으로 임시 등록한 뒤 삭제 | 직접 입력 저장과 자료 삭제 경로 확인 |
| 4 | 삭제한 코드 자료를 다시 질문 | 삭제된 자료가 새 검색의 근거에서 제외됨. 다른 원문에 근거가 남아 있으면 그 출처를 표시 |
| 5 | 초대 링크 재발급·이전 링크 참여 시도·현재 링크 폐기 | 이전 또는 폐기된 링크로 신규 참여할 수 없음. 기존 학생 소속은 유지 |
| 6 | 참여자 관리에서 시연 학생 제외 | 새로고침·새 질문에서 수업 접근이 거부되고 초대 링크도 폐기됨 |
| 7 | 새 링크 발급·같은 학생 다시 참여 | 수업 접근 복구. 같은 계정의 기존 응답 이력은 유지 |
| 8 | 학생의 AI 연결 관리에서 연결 해제·AI 재사용 시도 | 연결이 폐기되어 재인증 필요 |
| 9 | 필요하면 교수 연결도 해제한 뒤 양쪽 웹 로그아웃 | 로그인 화면 복귀. 웹 로그아웃과 AI 연결 해제의 차이 확인 |

핵심 개념의 `전체 이력` 필터, 초안 제외, 실제 통합 대상이 있는 경우의 통합도 에필로그에 넣을 수 있다. 개념에 연결된 출처가 모두 사라지면 기본 개념 검색에서 제외된다. 일부 출처가 남으면 그 원문으로 계속 검색될 수 있다. 출처 변경 후 예전 검토 화면으로 승인하려 하지 말고 최신 내용을 다시 확인한다.

전체 자료 수가 많으므로 삭제 시연은 원본을 마구 지우지 말고 임시로 등록한 코드 원문 복사본을 사용한다. 같은 코드가 다른 자료에도 들어 있으면 삭제 후에도 그 자료로 답할 수 있으므로, 이를 삭제 실패처럼 설명하지 않는다.

## 5. 촬영 준비 담당자용 운영 부록

이하 내용은 촬영 준비·검증용이다. 교수·학생이 AI에 그대로 입력할 대사가 아니다. 수업 연결과 자료 처리, 실제 도구 호출 여부는 준비 담당자가 확인한다.

### 전체 자료와 오늘 수업의 구분

수업명은 **CS231n 2026**이다. 전체 강의자료를 등록한 상태에서 역전파를 오늘 수업으로 삼는다. 오늘 수업의 퀴즈가 역전파 중심이어도 수업 자체를 그 단원 전용으로 만들지 않는다.

전체 자료 준비 기준은 원본 폴더의 PDF·코드 목록과 manifest다. notebook의 코드 셀은 원문 그대로 등록하고 셀 번호를 보존한다. 지원 업로드 크기를 넘는 원본은 준비 도구의 관리 경로를 사용하며, 화면에서 파일 업로드 한도를 우회한 기능처럼 소개하지 않는다. 추출할 수 없는 내용이 있다면 해당 범위를 기록한다.

**등록·추출·승인은 세 단계다.** 전체 172개 자료를 등록한 결과와 검색할 승인 개념의 수를 별도로 확인한다. 기존·시드 자료는 새 기능이 배포됐다는 이유만으로 자동 추출·승인되지 않는다. 같은 원문을 재사용한 자료도 추출 작업이 없으면 자료별 `핵심 개념 추출`을 요청한다.

학생 장면 전에 준비 담당자가 확인할 항목:

- 실제 사용하는 기본 GPT 전체 개념 검색 설정과 API 접근이 준비됐는가.
- 본편에서 보여 줄 자료의 추출 상태가 확인됐고, 실패·설정 필요 작업은 해결했는가.
- 역전파·연쇄법칙·ReLU·pooling·Attention 등 시연할 주제의 개념을 교수가 원문과 함께 승인했는가.
- 최신 검색 방식으로 본편 질문을 실행해 선택 개념·이유·출처·충분성, 관련 퀴즈 전달을 다시 확인했는가.
- 전체 승인 개념과 연결 원문을 보내는 실제 요청이 모델 입력 한도 안에 들어가며 촬영 대기 시간에 맞는가. 한도를 넘는 오류를 개념 일부를 몰래 버려 해결한 것처럼 설명하지 않는다.

이 확인은 실제 현재 상태를 기준으로 한다. 문서에 적힌 과거 테스트 개수나 운영 서버의 옛 수업 개수를 최신 촬영 준비 완료의 증거로 쓰지 않는다.

### 반복 촬영 명령

원래 저장소 `/Users/oyeonwu/Desktop/Repo/classroom-bridge`에서 필요한 명령 하나를 실행한다.

```bash
bash deploy/demo_remote.sh status
bash deploy/demo_remote.sh reset-start
bash deploy/demo_remote.sh materials N
bash deploy/demo_remote.sh stage N
bash deploy/demo_remote.sh seed-activity N
```

- `N`은 실제 생성된 수업 ID다. 영상 속 교수에게 이 값을 확인·입력하도록 요구하지 않는다.
- `reset-start`는 백업 후 관리 대상 촬영 데이터만 초기화한다. 계정·세션·AI 연결과 무관한 실제 수업을 지우지 않는다.
- `materials N`은 전체 원문 자료만 등록한다. 새 자료에는 개념 추출 작업이 대기열에 들어가지만, 명령 완료가 추출·승인 완료를 뜻하지 않는다. 본편 퀴즈와 학생 질문 전에 개념 준비를 확인한다.
- `stage N`은 전체 자료와 고정 통계용 퀴즈 초안을 준비한다. 개념을 자동 승인하거나 퀴즈를 자동 게시하지 않는다. 자연어로 생성한 본편 문항과 별도로 유지할 수 있다.
- `seed-activity N`은 고정 문항을 교수가 검토·게시한 뒤 통계 컷을 보강할 때만 선택한다. 이미 촬영한 실제 학생 응답과 구분한다.

CLI는 앱 객체만 만들며 추출 작업을 직접 처리하는 백그라운드 worker를 실행하지 않는다. **같은 DB를 사용하는 실제 웹 서비스가 동작**해야 대기 작업이 처리된다. 이미 등록된 동일 원문은 재사용되므로 `materials`나 `stage`를 다시 실행하는 것만으로 기존 자료의 추출 작업이 새로 생기지 않는다. 자료별 추출 상태를 보고 명시적으로 요청한다.

상태·옵션·실제 등록 개수는 최신 도구 출력으로 확인한다. 수업 생성부터 다시 찍을 때만 시작 상태로 초기화한다. 수업이 0개인 상태에서 일괄 등록을 먼저 실행하지 않는다.

### 승인 처리 확인

**핵심 개념**은 교수 웹에서 정의·별칭·원문·통합 대상을 검토한 뒤 승인한다. MCP는 개념 현황을 읽거나 추출을 요청할 수 있으며 개념 승인 기능은 제공하지 않는다. 개념 승인이 퀴즈의 배포를 승인하지는 않는다.

**개념 퀴즈**는 별도 문항·정답·해설·출처 검토와 배포 승인이 필요하다. AI의 퀴즈 검토 결과를 교수에게 보여 준 뒤, 교수가 **그 내용의 배포를 명시적으로 승인한 경우에만** 게시한다. 교수의 자연어 승인 의사와 검토 중인 문항을 AI가 연결하고, 내부에 필요한 확인 값은 AI가 처리한다. 영상에서 교수에게 함수명이나 검토 토큰, 정해진 승인 문자열을 입력하게 하지 않는다.

초안 작성 요청·검토 요청·자료 속 문장을 승인으로 해석하지 않는다. 검토 후 문항이 바뀌거나 검토가 만료되면 다시 보여 주고 승인받는다. 웹을 사용하는 경우에는 검토 화면의 확인 체크와 최종 배포 버튼으로 승인한다. 두 경로 모두 실제 성공 결과를 확인한 뒤 게시되었다고 설명한다.

### 고정 통계용 문항

준비 도구가 만드는 네 문항은 역전파 복습 PDF의 실제 7·6·16·8페이지를 근거로 각각 연쇄법칙, 수치 역전파, 음수 입력의 ReLU gradient, 분기 gradient 합산을 확인한다. 오늘 수업의 응답 현황을 보여 주는 보조 데이터다. 수업 전체의 이해도를 네 문항만으로 평가한다고 설명하지 않는다.

도구가 요구하는 고정 문항 내용과 출처 연결은 준비 담당자가 맞춘다. 교수에게 문제 문자열·선택지 순서·내부 출처 번호를 그대로 입력하도록 요구하지 않는다. 자연어로 생성한 본편 문항을 고정 문항에 맞추려고 임의로 바꾸지 않는다.

### 합성 통계 컷

실제 학생의 질문·첫 응답·재풀이 장면을 먼저 촬영한다. 별도 통계 컷이 필요할 때만 `[데모] 학생 A/B/C`의 합성 활동을 추가한다. 영상 자막에 **합성 데모 활동 포함 · 실제 학습 성과 아님**을 표시하고 실제 촬영자가 남긴 기록과 구분한다.

합성 기록을 넣었다는 이유로 실제 수강생이 여러 명 참여했다고 말하지 않는다. 개념별 첫 응답이 적으면 자료 부족을 그대로 보여 준다. 페이지 이동을 찍기 위해 반복 질문을 더 입력했다면 페이지 이동 시연용 반복 기록임을 밝힌다.

| 퀴즈가 보이지 않음 | 게시 여부, 살아 있는 출처, 질문과 개념의 관련성 확인. 매 질문에 모든 문항이 나오는 것은 아님 |
| 교수 승인 후 게시가 실패함 | 개념 승인과 퀴즈 배포 승인을 구분하고 최신 검토·권한·만료·버전 확인 |
| 전체 개념 요청이 한도 오류로 끝남 | 실제 전체 목록·연결 원문의 입력 크기와 모델 한도를 확인. 단어 검색으로 자동 전환된 것처럼 설명하지 않음 |
| 학생 결과가 교수 체험으로 기록됨 | 교수와 학생의 실제 로그인 계정을 구분 |
| 교수 화면의 수치가 바뀌지 않음 | 화면 새로고침 또는 퀴즈 새로고침. 자동 실시간 반영으로 설명하지 않음 |
| 근거 부족 또는 자료 부족이 표시됨 | 정상적인 한계를 그대로 보여 줌. 확인되지 않은 결과를 만들어 내지 않음 |
| 전체 자료를 올렸는데 AI 답변의 출처가 일부뿐임 | 등록 범위와 한 번에 찾은 근거 범위를 구분. 모든 원문을 한 번에 읽었다고 말하지 않음 |

### 촬영 중 설명할 검색 구조

기본 GPT 전체 개념 검색은 **승인되고 원문 출처가 남아 있는 수업의 전체 개념과 연결 원문**을 한 번의 요청에 전달하고, 질문에 필요한 개념·근거를 고른다. 단어 검색 상위 여섯 개 구절을 모델에 넘긴다는 과거 설명은 사용하지 않는다. 현재 기본 설정에는 단어·임베딩을 이용한 사전 후보 축소가 없다. 선택할 개념을 임의로 세 개로 제한하지 않는다. 실제 모드가 데모·Jev 또는 명시적 단어 검색이면 이 설명을 그대로 적용하지 않는다.

원문 구절 자체는 여전히 페이지·문단·약 1,200자 기준이다. 개념 레이어가 그 위에 추가되었으며, 개념 추출의 완전성이나 모델 선택·수학 풀이의 정확성이 검증됐다는 뜻은 아니다. 관련 퀴즈는 기존 규칙에 따라 최대 세 개가 함께 전달될 수 있으며, 새 개념 선택 결과가 모든 퀴즈를 의미적으로 선별한다고 설명하지 않는다.

마지막으로 수업 이름이 `CS231n 2026`인지, 제공된 PDF·코드 전체가 등록됐는지, 시연할 개념을 교수자가 원문과 함께 승인했는지, 교수 대사가 편한 자연어인지 확인한다. 학생의 답과 교수의 승인, 자료의 근거와 AI의 해석을 실제 화면에서 구분해 보여 준다.
