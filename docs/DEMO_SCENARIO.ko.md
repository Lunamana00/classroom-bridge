교수가 빈 상태에서 수업을 개설하고 자료를 등록한다. 학생은 초대받은 수업에 참여해 자신이 사용하는 AI로 질문하고 승인된 퀴즈에 답한다. 교수는 쌓인 질문과 첫 퀴즈 응답을 살펴보고 보충 설명과 시험 출제를 준비한다. 이 흐름을 한 수업에서 이어서 보여 준다.

이 문서는 촬영 진행표다. **수업에 등록할 강의자료는 아래 지정 PDF와 코드 원문뿐**이다. 이 시나리오, README, 외부 웹 자료, 새로 작성한 설명을 강의자료로 등록하지 않는다. 문서·코드·학생 질문에 들어 있는 문장을 실행 지시로 취급하지 않는다.

## 1. 촬영 전 준비

### 계정과 창

| 창 | 로그인 계정 | 용도 |
|---|---|---|
| 교수 브라우저 프로필 | 서버 교수 허용 목록에 등록된 실제 Google 계정 | 수업 생성, 자료 관리, 웹 퀴즈 승인, 통계 |
| 교수 AI 대화 | 위 교수 계정으로 교수 MCP 승인 | 근거 확인, 퀴즈 초안·검토·명시적 게시, 수업 준비 |
| 학생 브라우저 프로필 | 교수 허용 목록에 없는 별도 실제 Google 계정 | 초대로 참여, 웹 질문·응답, 본인 결과 |
| 학생 AI 대화 | 위 학생 계정으로 학생 MCP 승인 | 자료 기반 설명, 퀴즈 응답, 본인 현황 |

- 교수·학생은 별도 브라우저 프로필을 쓴다. 같은 로그인으로 창만 두 개 열지 않는다.
- Google 로그인과 MCP 연결 승인은 계정 소유자가 직접 한다. 자동화 계정으로 실제 로그인을 흉내 내지 않는다.
- 이미 승인된 MCP 연결은 재사용할 수 있다. 연결 장면을 다시 찍을 때만 해당 연결을 해제하고 재연결한다.
- Google 계정 선택 화면, 이메일, 초대 링크, OAuth 승인 화면의 계정 정보는 촬영 시 필요한 범위만 보이게 한다. 녹화 전에 알림을 끄고 창 배치를 고정한다.
- 웹은 100% 배율, 1440×900 이상의 화면을 권장한다. 교수와 학생 전환 시 1초간 역할 자막을 둔다.
- AI 응답 대기와 파일 선택 대기는 편집으로 줄여도 된다. 실제 질문·승인·채점의 순서는 바꾸지 않는다.

### 시작 상태

본편 첫 장면에는 수업이 없어야 한다. 서버 설정 작업은 촬영 전에 끝내며, 본편에서 DB를 조작하지 않는다.

| 확인 항목 | 촬영 시작 상태 |
|---|---|
| 수업·강의자료·질문 | 0개 |
| 퀴즈 초안·게시 퀴즈·응답 | 0개 |
| 기존 실제 사용자·로그인·AI 연결 | 보존 가능. 강의 데이터 초기화와 별개 |
| 기본 예시 수업 자동 생성 | 재시작 후에도 억제 |
| 리허설 질문·합성 통계 | 없음 |

초기화는 SQLite 백업을 먼저 만들고 촬영 대상 데이터에만 수행한다. 실제 수업이 추가로 생겼다면 전체 DB를 지우지 않는다. 실제 운영 상태는 준비 작업의 `status` 출력으로 확인한다. 아래 `stage`와 `seed-activity`는 **선택 사항**이며, 실행 전까지 준비된 수업·통계가 있는 것으로 설명하지 않는다.

**교수 직접 행동**: 화면의 문항·정답·출처를 검토한 뒤 **방금 반환된 승인 문구를 그대로 직접 입력**한다. ID와 버전은 촬영 때 결정된다. 미리 작성한 임의 문구나 이 문서의 예시를 전송하지 않는다. 서버가 요구하는 정확한 문구가 아닌 막연한 “승인합니다”만으로는 게시되지 않는다.

**기대 결과**: `publish_concept_quiz` 성공 결과의 상태가 `published`가 된다. 웹 새로고침 후 같은 문항이 `배포 중`으로 보인다. 검토만 했을 때는 여전히 초안이다.

**웹 직접 작성**

1. `개념 퀴즈 → 퀴즈 초안 만들기`에서 부록 문항 2를 입력한다. PDF 6페이지의 실제 원문 구간을 근거로 선택한다.
2. `초안 저장` 후 `초안 수정`을 열어 내용을 점검하고 다시 저장한다. 정답·제목 등 최종 내용은 부록과 동일하게 유지한다.
3. `검토 후 배포`를 열어 문제·정답·출처를 읽는다.
4. 확인 체크박스를 누르고 `승인하고 학생에게 배포`를 클릭한다.
5. 문항 3·4도 동일한 방식으로 저장·검토·게시한다. 반복 입력은 편집으로 줄일 수 있다.

**내레이션**

> AI의 제안은 초안입니다. 교수는 정확한 문항과 출처를 검토하고 명시적으로 배포를 승인합니다. AI 대화에서 승인할 수도 있고 웹에서 직접 승인할 수도 있습니다. 게시된 내용은 수정할 수 없으므로 바꾸려면 새 초안을 만듭니다.

**입력 시간을 줄이는 선택 방법**: 앞 장면에서 수업 생성과 자료 등록을 촬영한 뒤 녹화를 잠시 멈추고 `stage --course-id N`을 실행할 수 있다. 누락 자료·표준 초안을 보완하는 용도다. 자동 게시하지 않으므로 반드시 다시 교수 화면에서 검토·승인을 촬영한다. 이미 존재하는 동일 원문을 중복 업로드하지 않는다.

### 장면 6. 학생 웹에서 질문과 첫 답 제출 · 08:00–10:00

**학생 웹에 입력할 질문**

```text
upstream gradient와 local gradient는 backpropagation의 chain rule(연쇄법칙)에서 어떻게 결합하나요?
```

**화면 동작**

1. `학생 질문 체험`에서 질문하고 `자료에서 찾기`를 누른다.
2. 근거 발췌, 근거 충분성, 자료 제목·페이지가 보이게 한다.
3. 출처를 눌러 원문을 연다. 답변 지시문도 열고 복사 기능을 보여 준다.
4. 관련 개념 퀴즈가 나타나면 **문항 제목을 보고 문항 1을 선택**한다. 전달 순서·개수는 검색 결과와 관련성에 따라 달라질 수 있다.
5. 데모에서는 학생이 문항 1(`[데모] 연쇄법칙: upstream × local`)의 오답 **B**를 직접 고르고 `답 제출 · 채점`을 누른다.
6. 제출 뒤 표시되는 정오답·정답·해설을 확인한다. 학생의 `나의 개념 퀴즈 응답`에서 첫 응답과 자료 부족 상태를 보여 준다.

**기대 결과**: 질문이 기록되고 서버가 오답으로 채점한다. 미응답 문항은 오답으로 집계되지 않는다. 제출 전에는 퀴즈 정답·해설이 공개되지 않고 제출 뒤 공개된다.

**내레이션**

> 웹에서는 자료 발췌와 출처를 먼저 확인합니다. 이 화면의 발췌는 생성된 설명이 아닙니다. 승인된 퀴즈에 학생이 직접 답하면 서버가 채점하고 첫 응답을 기록합니다.

교수 화면으로 잠깐 전환해 같은 질문을 체험하고 문항 1에 답하면 `교수 미리보기 · 집계 제외`를 확인할 수 있다. 교수의 풀이는 학생의 첫 응답 수에 추가되지 않는다. 교수 미리보기 질문 자체는 질문 DB에 기록된다는 점은 구분한다.

### 장면 7. 학생 AI의 설명·재풀이·본인 현황 · 10:00–12:30

**화면 동작**

1. 학생용 MCP 주소로 별도 실제 학생 계정의 연결 승인을 진행하고 학생용 지시문을 적용한다.
2. 다음을 요청한다.

```text
list_courses로 제가 참여한 수업을 확인해 주세요. '[촬영] CS231n 2026 · Backpropagation'을 사용하겠습니다. 이 수업의 chain rule(연쇄법칙)에서 upstream gradient와 local gradient가 어떻게 결합하는지 한국어로 설명해 주세요.
search_course_materials를 한 번 호출하고 반환된 PDF 제목과 페이지를 인용해 주세요. 관련 퀴즈가 있으면 문항 1을 먼저 보여 주고 제 답을 기다리세요. 정답을 대신 선택하거나 제출하지 마세요.
```

3. 자료에 근거한 외부 LLM의 자연어 설명과 출처를 보여 준다.
4. 학생이 새로 전달된 **문항 1**에 직접 답한다.

```text
문항 1에 대한 제 답은 A입니다. 지금 제시한 문항 1의 delivery_id로 이 답만 submit_quiz_answer에 전달하고 서버 채점 결과를 알려 주세요.
```

5. 다음을 요청한다.

```text
get_my_quiz_progress로 제 응답 현황을 보여 주세요. 문항 1의 최초 오답과 방금 재풀이 정답을 구분하고 첫 응답 집계가 바뀌었는지 설명해 주세요. 관측 수가 적으면 자료 부족이라고 표시해 주세요.
```

**기대 결과**: 서버는 새 delivery의 정답을 재풀이로 기록한다. 첫 응답 오답은 유지된다. LLM이 응답 정확성을 임의 판정하지 않고 서버 결과를 전달한다.

필요하면 이어서 질문한다.

```text
다음 질문을 search_course_materials에 그대로 전달해 주세요.
numeric backprop 수치 역전파: Backward pass에서 x=-2, y=5, z=-4일 때 upstream gradient는 어떻게 흐르나요?
반환된 설명 근거를 인용하고, 관련 퀴즈 문항 2를 보여 준 뒤 제 답을 기다려 주세요.
```

문항 2에 답한 뒤 다음을 요청한다.

```text
다음 질문을 search_course_materials에 그대로 전달해 주세요.
branch gradient 분기 gradient에서 Copy / branch의 gradient는 어떻게 결합하나요?
반환된 설명 근거를 인용하고, 관련 퀴즈 문항 4를 보여 준 뒤 제 답을 기다려 주세요.
```

실제로 해당 문항이 전달되었을 때만 문항 2에 `-4`, 문항 4에 `합산`을 직접 입력한다. 다른 문항의 delivery_id를 재사용하지 않는다. 문항이 없으면 개념 키워드로 한 번 새 검색하고, 계속 없으면 웹에서 해당 개념을 질문하여 정상 전달을 확인한다. AI가 미전달 문항의 ID를 추측하게 하지 않는다.

**내레이션**

> 학생이 평소 사용하는 AI가 자료를 받아 최종 설명을 작성합니다. 퀴즈의 채점과 기록은 서버가 맡습니다. 다시 맞혔다고 최초 오답이 사라지지는 않습니다.

### 장면 8. 코드 질문과 근거 부족 · 12:30–13:30

```text
grad_xw1 = self.grad_h * (self.h > 0)에서 ReLU mask가 필요한 이유는?
```

**기대 결과**: 등록 자료에 해당 공지가 없으므로 근거 부족이 표시된다. AI도 시험 날짜·장소를 만들어 내지 않는다.

**내레이션**

> 코드의 어느 줄이 근거인지 확인할 수 있습니다. 반면 등록한 PDF와 코드에 없는 시험 일정은 답할 수 없다고 알립니다.

|---|---|---|
| A | 사용하지 않는 새 퀴즈 초안 하나를 만들고 `초안 보관` | 배포되지 않은 초안이 보관 상태로 전환 |
| B | 문항 3의 `배포 중단` 후 학생이 ReLU 재질문 | 해당 문항은 새로 전달되지 않음. 기존 응답 이력은 유지 |
| C1 | `강의자료 → 직접 입력`에 셀 18 코드 원문 전체를 붙여 넣고 `입력 경로 확인용` 제목으로 임시 등록 | 웹 텍스트 직접 저장 기능 확인. 강의 내용은 지정 코드 원문 그대로 |
| C2 | 방금 임시 등록한 코드 자료와 원래 셀 18 자료 삭제 후 numerical_gradient 재질문 | 삭제한 코드가 새 질문의 근거에서 제외. 자료 2개 |
| D | `학생 초대` 재발급 → 이전 링크로 참여 시도 | 이전 링크 만료 안내. 이미 참여한 학생의 소속은 유지 |
| E | 최신 초대 링크 `링크 폐기` | 그 링크로 새 참여 불가 |
| F | 교수 `참여자 관리 → 참여 제외` | 실제 학생의 수업 소속 제거. 현재 초대 링크도 폐기 |
| G | 학생이 새로고침 또는 MCP 검색 | 해당 수업 자료·도구 접근 거부. 이전 브라우저 화면 캐시와 새 접근 결과 구분 |
| H | 교수 새 링크 발급 → 학생 다시 참여 | 같은 실제 계정의 수업 접근 복구 |
| I | 학생 `AI 연결 관리 → 연결 해제` → 학생 MCP 호출 | 연결의 토큰이 폐기되어 재인증 필요 |
| J | 교수 연결도 필요시 해제 → 양쪽 웹 로그아웃 | 로그인 화면 복귀. 웹 로그아웃과 MCP 연결 해제는 별도 |

학생 제외와 재참여를 같은 계정으로 진행하면 기존 응답 이력이 계정에 연결되어 남는다. 교수의 주 계정을 참여 제외 대상으로 사용하지 않는다. 배포 중단한 문항은 같은 문항 ID로 재게시할 수 없으므로 다시 촬영할 때는 새 초안을 만든다.

## 5. 표준 퀴즈 4개

각 문항은 지정 PDF 원문을 근거로 만든 **촬영용 연습 문항**이다. CS231n 원문에 이미 실린 시험 문제라고 설명하지 않는다. `source_chunk_ids`는 현재 수업에서 해당 PDF 페이지를 담은 실제 ID로 지정한다. 여러 구간으로 나뉘었다면 문제와 정답을 확인할 수 있는 구간을 선택한다.

### 문항 1 · PDF 7페이지 · 객관식

```text
제목: [데모] 연쇄법칙: upstream × local
관련 개념: chain rule, 연쇄법칙
유형: multiple_choice
문제: Backpropagation에서 각 노드가 입력 쪽으로 전달할 gradient는 어떻게 계산하나요?
선택지 A: upstream gradient × local gradient
선택지 B: 두 gradient를 더한다
선택지 C: local gradient만 사용한다
선택지 D: 순전파 출력만 사용한다
정답: A
허용 답안: 없음
해설: 복습 PDF 7쪽은 upstream gradient와 local gradient를 곱하여 입력 방향의 gradient를 전달하는 연쇄법칙을 보여 줍니다.
출처: PDF 7페이지의 실제 첫 구간 ID 1개
```

### 문항 2 · PDF 6페이지 · 단답형

```text
제목: [데모] 수치 역전파: ∂f/∂x
관련 개념: numeric backprop, 수치 역전파
유형: short_answer
문제: f=(x+y)z, x=-2, y=5, z=-4일 때 ∂f/∂x의 값은? 숫자만 입력하세요.
선택지: 없음
정답: -4
허용 답안: −4
해설: 복습 PDF 5~6쪽 계산 그래프에서 ∂f/∂x=z=-4입니다.
출처: PDF 6페이지의 실제 첫 구간 ID 1개
```

허용 답안은 ASCII `-`가 아니라 유니코드 마이너스 `−`를 쓴 `−4`다. `-4.0`은 이 표준 문항의 허용 답안이 아니다.

### 문항 3 · PDF 16페이지 · 객관식

```text
제목: [데모] ReLU의 음수 입력 gradient
관련 개념: ReLU
유형: multiple_choice
문제: 복습 PDF의 ReLU backward에서 입력이 -2일 때 local gradient는?
선택지 A: 0
선택지 B: 1
선택지 C: -2
선택지 D: 정해지지 않는다
정답: A
허용 답안: 없음
해설: 복습 PDF 16쪽의 ReLU는 음수 입력의 gradient를 0으로 막고 양수 입력에서 전달합니다.
출처: PDF 16페이지의 실제 첫 구간 ID 1개
```

표준 문항 3의 출처 ID는 PDF 16페이지 1개로 유지한다. 셀 11의 mask 연결은 코드 질문 장면에서 별도로 설명한다.

### 문항 4 · PDF 8페이지 · 단답형

```text
제목: [데모] 분기 경로의 gradient 합산
관련 개념: branch gradient, 분기 gradient
유형: short_answer
문제: 계산 그래프의 분기 경로에서 돌아오는 gradient들은 어떻게 결합하나요? 한 단어로 답하세요.
선택지: 없음
정답: 합산
허용 답안: 합산한다
허용 답안: 더한다
허용 답안: sum
해설: 복습 PDF 8쪽의 분기에서는 각 경로에서 돌아온 gradient를 더합니다.
출처: PDF 8페이지의 실제 첫 구간 ID 1개
```

위 네 문항의 제목·개념 순서·문제·선택지·정답·허용 답안·해설·출처 ID는 `deploy/demo_setup.py`의 `quiz_payloads`와 맞춘다. `seed-activity`는 정확히 일치하는 네 문항이 게시되어 있어야 실행된다. 문구를 수정해 시연했다면 표준 값으로 되돌려 다시 검토·게시하거나, 변경한 문항을 별도 문항으로 유지하고 표준 문항을 새로 준비한다.

단답형은 정규화된 완전 일치로 채점한다. 예를 들어 허용 답안에 없는 긴 서술은 의미가 비슷해도 오답이 될 수 있다. 촬영에서는 위에 지정한 짧은 정답을 실제 학생이 입력한다.

## 6. 반복 촬영용 운영 명령

운영 서버에는 `deploy/demo_remote.sh` 래퍼를 사용하면 된다. 저장소 루트에서 실행하며 기존 `oracle` SSH 설정과 서버의 비공개 환경 파일을 사용한다.

```bash
bash deploy/demo_remote.sh status
bash deploy/demo_remote.sh reset-start
bash deploy/demo_remote.sh stage N
bash deploy/demo_remote.sh seed-activity N
```

한 번에 네 명령을 연달아 실행하라는 뜻이 아니다. `status`로 확인하고, 다시 처음부터 찍을 때 `reset-start`, 수업 개설 뒤 준비 컷에서 `stage N`, 승인 완료 뒤 합성 통계 컷이 필요할 때 `seed-activity N`을 선택한다. `N`에는 현재 촬영 수업의 실제 ID를 넣는다. `reset-start`는 기본 예시 수업과 `[촬영] CS231n` / `[리허설] CS231n` 접두사의 수업을 백업 후 삭제하고 계정·세션·OAuth 연결·무관한 수업을 보존한다. 무관한 실제 수업이 있다면 전체 수업 수는 0이 되지 않을 수 있다.

도구: `deploy/demo_setup.py`<br>
에셋: `output/demo/assets/`<br>
아래는 **로컬 DB용 예시**다. 운영 서버에서는 앱의 실제 DB·에셋·쓰기 가능한 백업 디렉터리의 절대 경로로 바꿔 실행한다. 로컬 명령 실행만으로 운영 서버가 바뀌지는 않는다. 운영 환경에서는 `--env-file /etc/classroom-bridge.env`로 기존 비공개 설정 파일을 지정할 수 있다. 비밀 값을 복사하거나 터미널에 출력하지 않는다. 명령의 최종 지원 옵션은 `--help`로 확인한다.

```bash
.venv/bin/python deploy/demo_setup.py status \
  --db data/classroom.sqlite \
  --assets output/demo/assets \
  --backup-dir data/demo-backups
```

```bash
.venv/bin/python deploy/demo_setup.py reset-start \
  --db data/classroom.sqlite \
  --assets output/demo/assets \
  --backup-dir data/demo-backups
```

`reset-start`는 촬영 시작 상태를 다시 준비하는 명령이다. 출력의 백업 위치와 남은 데이터 수를 확인한다. 기존 실제 계정·인증 정보를 지우는 도구로 사용하지 않는다. 수업 개설부터 다시 찍을 때 사용하며, 작업 뒤 브라우저를 새로고침한다.

**선택: 수업을 직접 만든 뒤 자료·초안 준비 시간을 줄이기**

```bash
.venv/bin/python deploy/demo_setup.py stage \
  --db data/classroom.sqlite \
  --assets output/demo/assets \
  --backup-dir data/demo-backups \
  --course-id N
```

`N`을 장면 1에서 만든 실제 수업 ID로 바꾼다. 수업 생성·자료 등록 장면을 먼저 촬영한 뒤 사용한다. 이미 등록한 원문은 중복 추가하지 않고 부족한 자료·표준 초안을 보완한다. 원문의 구간 내용이 같으면 파일명이나 등록 경로가 달라도 같은 자료로 인식한다. 따라서 웹에서 PDF·셀 11, MCP에서 셀 18을 등록한 뒤 실행하는 순서를 권장한다. 이 명령은 퀴즈를 자동으로 게시하지 않는다. 준비된 초안도 담당 교수가 실제로 검토하고 게시해야 학생에게 전달된다.

더 빠른 대안은 수업 개설 장면 직후 컷을 넣고 `stage`를 실행하는 것이다. 이 경우 PDF·셀 11·셀 18과 네 초안이 이미 준비된다. 자료 업로드 장면은 별도 삽입 컷으로 남기고, 셀 18을 다시 MCP로 중복 등록하지 않는다. 기존 표준 초안을 하나 열어 수정·검토·게시를 보여 주고, MCP 초안 생성과 웹 직접 생성은 **별도의 다섯 번째 시연 문항**으로 보여 준다. 다섯 번째 문항은 같은 지정 자료를 근거로 하고 촬영 후 보관한다. 네 표준 문항의 제목이나 내용을 바꾸어 대체하지 않는다. 모든 단계를 자연스러운 한 흐름으로 찍으려면 본편의 수동 등록 순서를 따른다.

**선택: 별도 통계 삽입 컷용 합성 활동**

```bash
.venv/bin/python deploy/demo_setup.py seed-activity \
  --db data/classroom.sqlite \
  --assets output/demo/assets \
  --backup-dir data/demo-backups \
  --course-id N
```

- 먼저 `stage --course-id N`으로 표준 자료·문항 연결 메타데이터를 준비하고, 표준 네 문항을 정확한 내용으로 게시한 뒤에만 사용한다. 수동으로 네 문항을 만들었더라도 `stage`를 한 번 실행해야 한다. 초안 상태에서는 실행하지 않는다.
- 실제 학생의 질문·첫 답·재풀이 장면을 먼저 촬영한다. 그 후 별도 통계 컷이 필요할 때 추가한다.
- `[데모] 학생 A/B/C`라는 합성 참여자를 사용한다. 이 계정들은 Google 로그인 사용자가 아니며 실제 학생인 것처럼 소개하지 않는다.
- 합성 질문은 `is_demo=1`로 구분한다. 수업 현황의 예시·직접 입력 질문 수를 함께 보인다.
- 영상 자막에 **“합성 데모 활동 3명 추가 · 실제 학습 성과 아님”**을 표시한다. 응답 통계의 표본 수에도 합성 활동이 포함됨을 설명한다.
- 합성 응답은 UI 기능을 보여 주는 예시이며 측정된 숙달도·실제 수강생의 성과가 아니다. 본편의 실제 학생 1명 기록과 구분한다.
- 합성 기록을 실제 운영 질문과 혼동하지 않도록 촬영 종료 후 보관 또는 시작 상태 초기화를 선택한다.
- 합성 질문은 12건이다. 페이지 이동까지 찍으려면 `전체 통계`의 현재 전체 질문 수를 확인한다. 20건 이하면 실제 촬영자가 앞의 자료 기반 질문을 명시적으로 반복 입력하여 총 21건 이상으로 만든 뒤 `다음 / 이전`을 보여 줄 수 있다. 이 경우 “페이지 이동 시연용 반복 질문 포함” 자막을 달고 질문 수를 실제 학생 수로 해석하지 않는다.

기본 전달 상태는 **수업이 없는 촬영 시작 상태**다. `stage`와 `seed-activity`는 사용자가 실행하거나 촬영 중 선택할 때에만 상태를 바꾼다.

## 8. 촬영 중 문제를 만났을 때

| 증상 | 확인·대응 |
|---|---|
| 수업 생성 버튼이 없다 | 교수 계정과 서버 허용 목록을 확인한다. 학생 계정을 교수로 바꾸는 임시 로그인은 만들지 않는다. |
| 학생에게 수업이 없다 | 같은 학생 프로필에서 유효한 초대 링크로 참여한다. 링크가 재발급·폐기되었는지 확인한다. |
| `.ipynb` 업로드가 실패한다 | 제공된 코드 원문 `.txt`를 사용한다. 앱의 파일 업로드 지원은 PDF/TXT/MD다. |
| 영어 자료인데 근거가 없다 | 질문에 원문의 영어 키워드를 포함한다. 후보 검색은 모델 호출 전 단어 기반이다. 실패를 성공으로 편집하지 않는다. |
| 코드 자료가 중복된다 | 셀 11은 웹, 셀 18은 MCP로만 등록한다. `stage` 실행 전후 자료 목록을 확인한다. |
| 퀴즈가 안 나온다 | 게시 상태, 살아 있는 근거 구간, 질문의 개념 일치부터 확인한다. 관련 퀴즈는 최대 3개이며 모든 문항이 항상 전달되는 것은 아니다. |
| MCP 게시가 거절된다 | 같은 교수·수업·문항·최신 버전의 review인지 확인한다. 10분 만료·새 검토·초안 수정 뒤에는 다시 검토하고 실제 승인을 받는다. |
| 학생 결과가 preview로 나온다 | 교수 계정으로 풀고 있는지 확인한다. 실제 학생 프로필의 새 질문에서 다시 전달받는다. |
| 재제출 답 변경이 거절된다 | 같은 delivery에는 한 답만 가능하다. 새 질문으로 새 delivery를 받아 재풀이한다. |
| 교수 화면이 갱신되지 않는다 | 브라우저 새로고침 또는 퀴즈의 `새로고침`을 누른다. 자동 실시간 갱신으로 설명하지 않는다. |
| 추정치 대신 자료 부족이 나온다 | 정상이다. 개념별 첫 응답이 3건 미만이면 자료 부족이다. 같은 문항 재풀이는 새 첫 응답이 아니다. |
| 모델 API 오류가 난다 | 키·모드·모델 권한을 서버에서 확인한다. 오류를 숨기거나 자동으로 다른 모델을 쓴 것처럼 설명하지 않는다. |
| 출제안이 전체 자료를 포함하지 않는다 | 컨텍스트는 등록 순서 앞 60개 구절까지다. 반환된 source_scope 범위를 화면에서 확인하고 포함 범위만 설명한다. |

마지막 확인: 첫 장면은 빈 상태였는지, 수업 자료가 지정 PDF·코드 3개뿐인지, 승인과 학생 답 입력을 실제 사람이 했는지, 자료 발췌·LLM 설명·서버 채점·응답 기반 해석을 구분했는지 확인한다.
