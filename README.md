# KHU조교 · KHUsistant

학생이 사용하는 LLM을 교수의 강의자료와 연결하고, 누적된 질문과 개념 퀴즈 응답을 수업 준비에 활용하는 웹 프로토타입입니다. 자료 등록 → 핵심 개념 추출·교수 승인 → 질문 → 관련 개념·원문 근거 선별 → 출처 확인 → 교수 승인 퀴즈 → 응답 현황 조회까지 한 화면에서 체험할 수 있습니다.

## 서비스 및 시연 영상

- 서비스: [canigetbus.app](https://canigetbus.app)
- 시연 영상: [YouTube에서 보기](https://youtu.be/uzTp-Pfw4EE)

## 바로 실행

Python 3.11 이상이 필요합니다. 저장소를 내려받은 뒤 프로젝트 폴더에서 실행합니다.

```bash
cd classroom-bridge
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
cp .env.example .env.local
# 아래 Google 로그인 설정에 따라 .env.local을 채운 뒤 실행합니다.
.venv/bin/python -m classroom
```

브라우저에서 [http://127.0.0.1:8000](http://127.0.0.1:8000)을 엽니다. Google 로그인 설정을 마친 뒤 허용된 교수 계정으로 로그인하면 예시 강의자료와 질문이 담긴 데모 수업으로 시작할 수 있습니다. 학생은 교수의 초대 링크로 수업에 참여합니다. 기본 설정은 FactChat API 키가 있으면 `gpt-6-luna`로 승인된 전체 개념을 검토하고, 없으면 단어 기반 데모 검색을 사용합니다. 전체 개념 검색은 개념 추출과 교수 승인을 먼저 마쳐야 하며, 데모 검색에서도 로그인과 수업 권한 검사는 적용됩니다.

1. 교수 화면에서 수업을 선택하거나 새로 만듭니다.
2. TXT·MD·텍스트가 포함된 PDF를 업로드하거나 강의 내용을 붙여 넣습니다. 파일당 최대 10MB이며, 스캔 PDF의 OCR은 지원하지 않습니다.
3. 핵심 개념 화면에서 추출 상태와 개념·설명·원문을 확인하고 승인합니다. 기존 예시 자료나 이전에 등록한 자료는 자료별로 추출을 요청한 뒤 승인하세요.
4. 학생 화면에서 “경사하강법이 뭐야?”처럼 질문합니다. 선별된 개념과 이유, 원문 자료, 출처, 외부 LLM에 전달할 답변 지시문을 확인합니다.
5. 교수 화면에서 질문 주제, 자료로 답할 수 없었던 질문, 보충 설명 지시문과 시험 출제안을 확인합니다.

데모 질문은 실제로 새로 입력한 질문과 구분해서 표시합니다. 데이터는 기본적으로 `data/classroom.sqlite`에 저장되며 서버를 재시작해도 유지됩니다.

## 자료 선별 방식 선택

기본값은 학생 질문과 **해당 수업의 승인되고 원문 출처가 남아 있는 전체 개념**, 연결된 원문 근거를 GPT에 한 번 전달하여 관련 개념과 답변 근거를 선별하는 방식입니다. 단어 일치나 임베딩으로 개념을 미리 줄이지 않으며, 여러 개념이 관련되면 함께 반환합니다. 공식 OpenAI Python SDK로 FactChat 게이트웨이를 호출합니다. GPT는 `responses.create()`, 기존 Jev 모드는 SDK의 `post()`로 `/decisions/`를 호출합니다. `.env.local`을 수정한 뒤 웹 서버를 재시작하세요.

```dotenv
CLASSROOM_MODE=auto
CLASSROOM_RETRIEVAL=concepts
OPEN_API_KEY=your-api-key
OPENAI_BASE_URL=https://factchat-cloud.mindlogic.ai/v1/gateway
CODEX_MODEL=gpt-6-luna
JEV_MODEL=jev-1.14.0
```

- `CLASSROOM_MODE=auto`: API 키가 있으면 `codex` 모드의 `gpt-6-luna`, 없으면 데모 검색을 사용합니다.
- `CLASSROOM_MODE=codex`: FactChat Responses API로 `CODEX_MODEL`을 호출합니다. 기본값은 `gpt-6-luna`입니다.
- `CLASSROOM_MODE=jev`: FactChat Decisions API로 `JEV_MODEL`을 호출합니다. 기본값은 `jev-1.14.0`입니다. 게이트웨이의 `state`·`questions` 형식으로 관련성·근거·주입 여부와 전체 충분성을 판단합니다. 실패 시 모델을 자동 교체하지 않습니다.
- `CLASSROOM_MODE=demo`: API 호출 없이 단어 기반 검색으로 체험합니다.

`CLASSROOM_RETRIEVAL=concepts`가 기본값이며, 키가 있는 `auto`와 `codex` 모드에서 전체 개념 선별을 사용합니다. GPT에 개념의 이름·설명·동의어·버전·연결 출처 ID와 중복을 제거한 연결 원문을 함께 보냅니다. 모델은 관련 개념을 0개 이상 선택하고 원문 근거와 충분성을 판단합니다. 개념 선택을 임의로 3개로 제한하지 않습니다. 반환된 개념과 선별 이유는 설명할 주제의 안내이며, 수학·공학 풀이의 정확성이나 증명을 검증한 결과가 아닙니다. 최종 설명은 반환된 원문 근거로 뒷받침해야 합니다.

승인된 유효 개념이 없으면 개념 준비가 필요하다는 안내와 빈 근거를 반환합니다. 승인 전 초안·제외·통합 이력이나 출처가 모두 삭제된 개념은 학생 검색으로 전달하지 않습니다. 전체 입력이 서버 또는 모델의 한도를 넘으면 오류를 표시하며 일부 개념·원문을 몰래 누락하거나 단어 검색으로 자동 전환하지 않습니다. API 호출 실패도 오류로 표시합니다.

기존 단어 기반 후보 검색을 사용하려면 `CLASSROOM_RETRIEVAL=lexical`로 지정하세요. `jev` 모드는 이 설정과 관계없이 기존 단어 기반 후보 검색 후 Jev 판단을 유지하고, `demo` 모드는 API 판단 없이 단어 검색을 사용합니다. 퀴즈의 최대 전달 개수와 기존 채점·승인 규칙은 그대로 적용됩니다.

`codex`·`jev`는 호환성을 위해 유지한 모드 이름입니다. Codex CLI 설치·로그인과 TypeSafe 키는 사용하지 않습니다. 키는 `OPEN_API_KEY` 또는 표준 이름인 `OPENAI_API_KEY`로 설정할 수 있으며, 둘 다 있으면 `OPEN_API_KEY`를 사용합니다. 설정 우선순위는 실행 환경변수 → `.env.local` → `.env`입니다.

학생이 자료 검색을 요청할 때 설정된 방식의 질문·개념·원문 자료를 FactChat 게이트웨이에 전달합니다. 기본 주소는 `https://factchat-cloud.mindlogic.ai/v1/gateway`이며 `OPENAI_BASE_URL`로 변경할 수 있습니다. 도구를 제공하지 않으며, JSON Schema 결과의 개념·자료 ID, 점수, 충분성을 검사하고 출처 원문을 보존합니다. GPT Responses 호출은 `store=false`를 사용하며, Jev는 Decisions API의 상태 보관 정책을 따릅니다. 실패는 오류로 표시하고 다른 모델이나 데모로 자동 전환하지 않습니다. 키는 서버에서만 사용하고 브라우저와 오류 메시지에 노출하지 않습니다. `.env`와 `.env.local`은 Git 추적 대상에서 제외됩니다.

모든 모드에서 앱의 답변 미리보기는 **자료 발췌**입니다. Codex와 Jev는 이 앱에서 근거 선별을 담당하고, 최종 자연어 답변은 MCP에 연결된 GPT·Claude·Gemini 등의 LLM이 작성합니다.

## Google 로그인과 수업 권한

Google Cloud Console의 Google Auth Platform에서 웹 애플리케이션 OAuth 클라이언트를 생성합니다. 로컬 테스트용 승인된 리디렉션 URI는 다음과 같습니다.

- `http://127.0.0.1:8000/auth/google/callback`
- `http://localhost:8000/auth/google/callback`

프로젝트의 `.env.local`에 설정한 뒤 서버를 재시작합니다. Google 클라이언트 시크릿은 채팅이나 Git에 넣지 않습니다.

```dotenv
GOOGLE_CLIENT_ID=your-client-id
GOOGLE_CLIENT_SECRET=your-client-secret
CLASSROOM_TEACHER_EMAILS=teacher@example.edu
CLASSROOM_BASE_URL=http://127.0.0.1:8000
```

Google Auth Platform에서 Branding과 Audience를 설정하고, External 테스트 상태에서는 로그인할 계정을 테스트 사용자에 등록합니다. 학교 Google Workspace 내부 사용자만 받을 경우 Internal을 선택할 수 있습니다. 범위는 `openid email profile`만 요청합니다. 서버 리디렉션 방식이므로 Authorized JavaScript origins는 필요하지 않습니다. Google 로그인은 Chrome·Safari 등 일반 브라우저에서 진행하세요.

교수 이메일은 쉼표로 구분합니다. 이메일이 인증된 Google 계정으로 로그인하며, 서버가 교수 허용 목록과 수업별 소속을 확인합니다. 학생은 초대 링크로 참여한 수업의 자료 조회·질문·퀴즈 응답·본인 응답 현황을 사용할 수 있습니다. 자료 변경·전체 질문 통계·퀴즈 검토와 승인·수업 응답 현황·시험 계획·초대·참여자 관리는 해당 수업의 담당 교수만 사용할 수 있습니다. 교수는 새 수업을 만들면 자동으로 담당자로 등록됩니다. 로그인 도입 전에 만들어진 수업은 **처음 로그인한 허용 교수**에게 귀속됩니다.

교수 화면의 학생 초대 버튼으로 7일 유효 링크를 만듭니다. 재발급·폐기할 수 있고 재발급하면 이전 링크가 만료됩니다. 참여한 학생의 권한은 링크 만료와 별개로 유지됩니다. 참여자 관리에서 학생을 제외하면 소속을 제거하고 기존 초대 링크도 폐기합니다. 다시 참여하려면 새 링크가 필요합니다.

로그인 세션은 7일 유효하며 서버 DB에 토큰의 해시만 저장합니다. 로그아웃 시 서버에서 폐기하며, 변경 요청은 CSRF 토큰을 검사합니다. Google OAuth 상태 쿠키의 서명 키는 `CLASSROOM_SESSION_SECRET`으로 지정하거나 서버 DB에 한 번 생성해 보관합니다. 개발 서버는 localhost에 바인딩하며, 운영 서버는 nginx의 HTTPS 프록시를 통해 제공합니다. 실제 Google 계정 로그인과 MCP 클라이언트 승인은 계정 소유자가 확인해야 합니다.

## MCP OAuth로 연결

OAuth를 지원하는 MCP 클라이언트에 다음 **Streamable HTTP** 주소를 추가합니다.

- 학생: `https://canigetbus.app/mcp/student`
- 교수: `https://canigetbus.app/mcp/instructor`

클라이언트가 서버의 인증 정보를 자동 탐색하고 등록한 뒤 Google 로그인과 연결 승인 화면을 엽니다. 로그인한 계정·클라이언트 이름·돌아갈 주소·학생/교수 권한을 확인하고 승인합니다. 교수용 연결은 교수 허용 목록에 있는 계정만 승인할 수 있습니다. 수업 소속과 담당 교수 권한은 도구 호출마다 다시 검사합니다. 학생은 참여하지 않은 수업을 조회하거나 교수 도구를 사용할 수 없습니다.

Google의 토큰은 MCP 클라이언트에 전달하지 않습니다. 앱이 MCP용 토큰을 별도로 발급하며, 토큰은 학생·교수 MCP 주소에 각각 묶입니다. PKCE S256, 2분 유효 일회용 코드, 1시간 접근 토큰, 최대 30일 갱신 토큰을 사용합니다. 갱신 시 토큰을 교체하고 이전 갱신 토큰의 재사용이 감지되면 해당 연결 전체를 폐기합니다. 워크스페이스의 **AI 연결 관리 → 연결 해제**에서도 토큰을 즉시 폐기할 수 있습니다. 웹 로그아웃과 AI 연결 해제는 별개입니다.

클라이언트 등록은 DCR(`POST /register`)로 지원합니다. 공개 클라이언트와 `client_secret_post`·`client_secret_basic`을 지원하며, 정확히 등록한 HTTPS 또는 loopback 리디렉션 주소만 허용합니다. CIMD URL을 원격으로 가져오는 등록 방식은 지원하지 않습니다. stdio는 계정 경계를 우회하지 않도록 지원하지 않으며, HTTPS MCP 주소를 사용합니다. 제품별 클라이언트 설정 형식은 다를 수 있습니다.

로컬 개발에서는 도메인 대신 `http://127.0.0.1:8000`을 사용합니다. 배포할 때 Google OAuth 클라이언트에 `https://canigetbus.app/auth/google/callback`을 추가해야 합니다. 새 MCP 클라이언트마다 Google Cloud Console 클라이언트를 만들 필요는 없습니다.

검증은 합성 계정으로 공식 MCP Python SDK의 자동 탐색·등록·PKCE 교환·도구 호출을 수행하고, 잘못된 verifier·다른 리소스·코드 재사용·만료·학생의 교수 권한 요청·수업 권한 제거·토큰 폐기를 확인합니다. 실제 Google 계정 로그인과 개별 ChatGPT/Claude/Codex 제품의 브라우저 승인 동작은 별도로 확인해야 합니다.

## 강의자료의 핵심 개념 전처리

자료를 업로드하거나 직접 입력하면 **핵심 개념 추출 → 중복 통합 제안 → 교수 검토·승인** 작업이 시작됩니다. 업로드 응답은 먼저 반환하고, 백그라운드 작업이 원문 전체를 나누어 처리합니다. 핵심 개념 화면에서 자료별 진행·실패 상태와 개념 초안을 확인할 수 있습니다. 기존 자료는 강의자료 또는 핵심 개념 화면에서 추출을 요청하세요.

각 개념에는 이름, 설명, 동의어, 자료 제목·페이지·원문 구절이 연결됩니다. 모델이 동일 개념으로 판단한 승인 개념을 통합 대상으로 제안하고, 이름·동의어가 일치하는 초안은 출처를 합칩니다. 다른 개념을 잘못 합치거나 중복을 놓칠 수 있으므로 교수는 원문과 함께 검토하고 이름·설명·동의어·출처·통합 대상을 수정할 수 있습니다. 수정 저장과 승인은 별도 동작입니다. 필요 없는 초안은 제외할 수 있습니다.

승인된 기존 개념에 새 자료를 연결하는 경우에도 통합 초안을 검토해야 합니다. 통합 승인은 기존 정의를 보존하고 검토한 별칭과 출처를 추가합니다. 원문 삭제나 동시 수정으로 검토 버전이 바뀌면 오래된 승인은 거부합니다. **승인된 개념과 남아 있는 출처가 기본 GPT 개념 검색의 대상**입니다. 추출 완료만으로 학생 검색에 반영되지 않으므로 교수 검토·승인을 마쳐 주세요. 기존 자료도 추출 요청과 승인을 거쳐야 하며, 기존 퀴즈의 선택·채점 규칙은 유지합니다.

```dotenv
CONCEPT_EXTRACTION_MODE=auto
CONCEPT_MODEL=gpt-6-luna
```

`auto`는 API 키가 있고 `CLASSROOM_MODE`가 `demo`가 아닐 때 자동 추출합니다. `api`는 질문 검색을 데모 모드로 유지하면서 개념 추출만 API로 실행할 때, `disabled`는 추출 API 호출을 끌 때 사용합니다. 모델을 지정하지 않으면 `CODEX_MODEL`, 그다음 `gpt-6-luna`를 사용합니다. 기존 `OPEN_API_KEY`/`OPENAI_API_KEY`와 `OPENAI_BASE_URL`을 사용하며, 자료 본문과 기존 승인 개념을 게이트웨이의 Responses API에 전달합니다. 도구 호출 없이 `store=false` 및 JSON Schema를 사용합니다. 실제 데이터 보관·과금은 게이트웨이 정책을 확인하세요.

API 미설정·실패는 자료별로 표시하며 단어 규칙으로 추출 성공을 가장하지 않습니다. 자료와 작업 상태는 SQLite에 보존됩니다. 처리 중 정상 종료하면 대기 상태로 되돌리고, 비정상 종료 작업은 임대 만료 후 다시 처리합니다. 실패한 작업은 설정을 수정하고 서버를 재시작한 뒤 추출을 다시 요청할 수 있습니다. 개념 검토·수정·승인은 담당 교수의 웹 화면에서만 가능하며 학생에게 초안은 노출하지 않습니다. 교수 MCP의 `list_course_concepts`로 현황을 읽고 `extract_material_concepts`로 기존 자료 추출을 요청할 수 있습니다.

## 개념 퀴즈와 응답 현황

1. 교수 LLM에 이해 확인용 퀴즈를 등록하도록 요청합니다. LLM은 `get_teaching_brief`의 자료 구절을 근거로 `propose_concept_quiz`를 호출해 **초안**을 저장합니다. 웹의 개념 퀴즈 화면에서 교수가 직접 초안을 작성할 수도 있습니다.
2. 교수 LLM은 `review_concept_quiz(course_id, quiz_id)`로 개념·문제·정답·해설·출처와 버전을 받아 교수에게 보여 줍니다. **교수가 해당 내용을 검토한 뒤 배포를 명시적으로 승인하면** `publish_concept_quiz`에 검토 토큰과 반환된 승인 문구를 전달합니다. 검토 토큰은 해당 교수·수업·문항·버전에 묶여 10분간 한 번만 유효하며, 내용이 바뀌면 다시 검토해야 합니다. 웹의 `review_url`에서 직접 검토·게시 승인할 수도 있습니다. 게시된 내용은 수정할 수 없으며, 변경이 필요하면 배포를 중단하고 새 초안을 만듭니다.
3. 학생이 개념을 질문하면 `search_course_materials`가 승인된 관련 퀴즈를 최대 3개 함께 보냅니다. 학생 LLM은 문제와 선택지를 보여 주고 학생의 실제 답을 기다립니다. 정답·허용 답안·해설은 제출 전에 전달하지 않습니다. [학생용 지시문](instructions/student.md)과 [교수용 지시문](instructions/instructor.md)을 클라이언트에 적용하세요.
4. 학생의 답을 `submit_quiz_answer(course_id, delivery_id, answer)`로 보내면 서버가 정답 여부와 정답·해설을 반환하고 기록합니다. 객관식은 선택지 ID, 단답형은 교수 지정 정답·허용 답안의 정규화된 완전 일치로 채점합니다. 단답형은 유니코드 표기·대소문자·연속 공백을 정규화하며, 의미가 비슷한 서술을 LLM으로 판정하지 않습니다.
5. 학생은 `get_my_quiz_progress`로 본인 결과를, 교수는 `get_quiz_insights`와 웹 화면으로 수업 및 학생별 개념 응답 현황을 봅니다. 보충 설명 지시문과 시험 출제안에도 퀴즈의 첫 응답 근거를 포함합니다.

퀴즈 전달 ID는 수업·로그인 계정에 묶이며 7일간 유효합니다. 같은 전달 ID와 같은 답을 재전송하면 기존 결과를 반환합니다. 답을 바꾸려면 새 질문으로 퀴즈를 다시 받아야 합니다. 재풀이는 기록에 남기되 **학생·문항별 첫 응답만** 개념 정답률과 추정에 사용하며, 교수의 체험 풀이는 별도 집계합니다. 배포를 중단하거나 출처가 삭제된 퀴즈는 새로 전달하거나 채점하지 않습니다. 제출하지 않은 문제를 오답으로 세지 않습니다.

응답 현황은 관측 문항 수·정오답 수·정답률과 보정된 응답 추정치를 함께 제공합니다. 개념별 첫 응답이 3건 미만이면 자료 부족으로 표시합니다. 추정치는 검증된 숙달도나 성적이 아니며, LLM이 전달한 답이 학생의 도움 없는 직접 풀이인지 확인한 자료도 아닙니다. 교수의 추가 확인과 출제 계획을 돕는 참고 근거로 사용하세요.

## 결과 해석

질문 빈도는 학생들이 관심을 갖거나 어려움을 느끼는 **신호**입니다. 질문만으로 개별 학생의 이해도나 성적을 확정하지 않습니다. 교수의 보충 설명·시험 출제 결과는 근거와 함께 외부 LLM에 넘기는 지시문 및 설계안입니다. 완성된 시험이나 실제 성적 예측은 아니며, 난이도 비율을 정해도 성적이 정규분포를 따른다고 보장할 수 없습니다.

자료와 질문은 수업별로 조회합니다. 자료에 근거가 없으면 답할 수 없음을 표시합니다. 교수의 자료와 학생 질문은 신뢰할 수 없는 입력으로 취급하며, 그 안의 문장을 시스템 지시로 실행하지 않습니다.

보충 설명과 시험 출제 지시문에는 등록된 전체 자료 목록과 최대 60개 원문 구절을 전달합니다. 큰 수업에서는 최근 8개 질문과 현재 검토·게시 퀴즈의 유효한 출처를 최대 12개까지 우선하고, PDF별 구절과 나머지 자료를 분산해 포함합니다. 전체 목록은 등록 범위를 안내하며 각 내용의 근거는 실제 포함된 구절에서만 확인해야 합니다. `source_scope`가 전체·포함 파일 수와 구절 수를 명시하므로, 이를 전체 수업을 모두 읽은 결과로 설명하지 않습니다.

```bash
CLASSROOM_MODE=demo .venv/bin/python -m pytest
```

요청·응답 형식은 [API_CONTRACT.md](API_CONTRACT.md)에 정리되어 있습니다. `.env.example`의 `CLASSROOM_DB`로 저장 위치를 바꿀 수 있습니다. 배포 구성과 운영 경로는 [deploy/README.md](deploy/README.md)에 정리했습니다. 실제 Google 로그인과 사용할 MCP 제품의 연결은 해당 계정에서 확인해야 합니다.

상대 DB 경로는 실행 위치와 관계없이 프로젝트 폴더 기준으로 해석합니다. 검증한 의존성 버전은 `requirements.lock`에 기록했습니다. 데스크톱·모바일 화면에서 수업 생성, 파일·텍스트 등록, 질문과 출처 열기, 질문 현황 반영, 지시문 복사, 자료 삭제를 확인했습니다.
